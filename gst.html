GST Reconciliation

Sales register vs e-invoice portal, for the GSTR-1 working · about 5 hours by hand, under 30 minutes with the tool

Every month, before GSTR-1 is filed, each invoice in the books has to be found on the e-invoice portal with the same taxable value and the same tax.

By hand that means two spreadsheets side by side, a VLOOKUP that breaks on INV/2025/001 vs INV-2025-001, and a person squinting at the leftovers. The tool cleans the numbers, matches them, scores the near misses, and writes one colour-coded workbook: a summary, then B2B, credit notes and HSN.

What this is, honestly. The matching below is a JavaScript copy of reconcile_invoices() in the public Python. The invoices and GSTINs are made up. Change any cell and run it again.

How one invoice gets matched

The same five steps run for B2B invoices and for credit notes. HSN summary lines are matched by HSN code instead.

  1. 1 · Load both sidessales register from the books, B2B sheet from the e-invoice portal; total rows dropped
  2. 2 · Clean the numberspaces, - and / removed, upper case: inv/2025/001 → INV2025001
  3. 3 · Exact matchsame cleaned number on both sides
  4. 4 · Near missno exact match? best look-alike on the portal, scored 0 to 100. 80 or more counts as a fuzzy match
  5. 5 · Compare taxtaxable, IGST, CGST and SGST, books minus portal. Any difference is a mismatch
Person Fuzzy matches and mismatches are flagged amber, missing invoices red. A person checks those before filing. Leftover portal invoices mean the books are missing something.
